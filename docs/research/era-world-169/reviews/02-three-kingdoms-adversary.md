## 3. 짝이 구체적으로 짚지 않은 결함

다음 세 건은 **실제 함수의 모델 선택을 추가 확인한 결함**이다. 내 12장 안에는 해당 연도·장소 근경이 없으므로 공개 화면에서 확인한 결함으로 표기하지 않는다. 원본 모듈을 메모리에서 불러오고 로컬 vendor Three를 사용했다. 경계 `x<4`인 가짜 해안과 평지, 이름 있는 인물 제거 조건이며, 원본 앱 파일은 수정하지 않았다. 결과는 `02-three-kingdoms-adversary-support.json`에 있다. 실제 지형·배의 접안·모델의 겹침·화면상의 크기는 이 실행으로 입증하지 않는다.

### A1. 우산국 해안의 위협 행위가 항구 운영으로 바뀐다

`history-scenes.json:963-970`은 512년 전선이 해안을 오가며 위협한 사건이며 상륙 지점은 모른다고 적는다. 그런데 장소의 `medium`은 육지 지역점이다. `chronicle-event-scenes.js:30`은 이 장소 매체를 따라 `sea=false`로 만들고, `:45`는 naval+ships를 `harbor`로 바꾼다. `:218-241`은 뜰집·탁자·수레·작업자·배 미끄럼틀·목재 더미를 만든다. 추가 실행에서도 `compositionKind=harbor`, 주 모델 `era_three_courtyard_0`이 나왔다.

**장면의 대표점이 육지라는 사실과 행위가 벌어진 매체를 혼동한 문제다.** 위협 항해와 배후 취락을 분리해야 한다. 정확한 항로·상륙지를 새로 꾸미지 않으면서도 해안 부근의 설명용 항해는 가능하다. ‘바다 사건을 모두 harbor로 통합’하는 수정도 그대로 같은 오류를 낸다.

### A2. 청해진 851년은 이주 대신 일반 모임 조합을 선택한다

`history-scenes.json:2192` 이하에는 철폐·주민 강제 이주와 기지 기능 종료가 있지만 `kind=assembly`, ships 효과는 꺼져 있다. `chronicle-event-scenes.js:291-300`은 이를 집 묶음과 15명의 일반 인물로 만든다. 추가 실행도 이 선택을 확인했다. 짝의 F04는 존속 기간 문제를 잘 짚었으나 **운영 이후 상태를 추가해도 851년 행위가 여전히 모임으로 남는 문제**가 있다.

주거 일부의 비어 감, 정리한 짐과 이동, 군사·교역 기능 종료를 구분해 그려야 한다. 강제 이주를 자발적 장터 방문처럼 처리하지 않는다. 다만 벽골군까지의 실제 경로·배 수·당일 전체 철거를 자료 없이 단정하지 않는다. 철폐 뒤 청해진 해군·무역 기지 기능이 사라진다는 것은 기관 해설에 근거가 있다. [청해진](https://encykorea.aks.ac.kr/Article/E0056856)

### A3. 사찰 이름 몇 개를 늘리는 방식으로는 해인사 착수 장면도 해결되지 않는다

`history-scenes.json:16362`의 802년 해인사 착수에는 완성 연도가 없다고 적혀 있다. `chronicle-event-scenes.js:36`의 사찰 단어 목록에는 해인사가 없고, 해당 요약은 ‘절’이라고 쓴다. 실제 선택은 일반 `construction`과 뜰집이었다. 모델 카탈로그에 사찰을 추가해도 이 분기 연결을 고치지 않으면 사용되지 않는다.

해결은 이름 정규식에 해인사 한 단어를 붙이는 데서 끝나면 안 된다. 사건이 다루는 대상(사찰·비·불상), 행위(착수·봉안·주조·수리)와 시설 상태를 구분하는 최소 정보가 필요하다. 해인사를 기존 `pagoda+hall`로 보내면 창건 착수와 확인되지 않은 완성형을 다시 혼동한다.

## 5. 시대·지역별 생활과 모델 묶음 보강

짝의 긴 모델 목록은 수집 목록으로는 유용하다. 구현 단위는 ‘물체 몇 종’보다 **사람이 재료를 가져와 만들고, 저장하고, 운반하며 사용하는 연결**이어야 한다. 아래는 설계 방향이며, 각 건물의 실측 위치·정확한 복식·공방 가동 연도가 확인됐다는 선언이 아니다.

| 시간·지역 | 먼저 읽혀야 할 생활 묶음 | 지속·변경 규칙과 한계 |
|---|---|---|
| 400년 국내성권, 427년 전후 평양권 | 거주·저장·물 이용 → 길 → 도성·방어 공간, 도시 밖 생산과 묘역. 귀족 거처와 보통 집의 기능·척도 구분 | 수도 이전은 왕궁·정치 역할의 변경이다. 국내성 생활이 즉시 사라지지 않게 한다. 안학궁 등 개별 왕궁의 연대·평면은 검토된 자료에 맞춰 따로 선택한다. |
| 600년 사비·금강권 | 왕성·관청과 주거, 물길의 나루·짐·창고·교환, 건축재 생산과 사찰·묘역 | 538년 이전·이후와 660년 이후의 지위·생활을 나눈다. 나루 좌표 미상은 실측 부두로 이름 붙이지 않되, 강 운송이라는 익명 생활 배경은 구성할 수 있다. |
| 4~6세기 가야 여러 중심, 600년 통합 뒤 낙동강권 | 철을 다루는 작업·연료·도구 수리, 토기·저장·화물 운반, 해안 취락과 여러 묘역 | 하나의 가야 수도·단일 양식으로 합치지 않는다. 생산 시설과 장례 유물은 근거가 다르다. 600년은 가야 정치체의 존속 증거가 아니며 생산·거주의 후속 상태를 확인하는 해다. |
| 600→645→646→800년 경주 | 왕성·생활 구역을 유지하며 사찰 공사에 목재·석재·노동·공양이 드나듦. 완공 후 승려·방문·보수로 행위 변경 | 645년의 공사·실명 인물과 사찰 수명을 분리한다. 800년 생활이 600년의 모델 ID를 그대로 쓰더라도 신설·증축·기능 변화의 근거가 있으면 공간에서 읽혀야 한다. |
| 800·920년 상경과 주변 생활권 | 중심 큰길과 궁성·행정·주거·시장·사찰, 난방·저장·수공업·농경과 물길 | 상경 한 곳의 화려한 건물로 발해 전체를 대표하지 않는다. 도시·일반 주거의 상세 형상은 자료 범위대로, 800년과 9세기 이후 상태는 따로 둔다. 918년 전역 교체를 막는다. |
| 828→830→850→851 이후 완도·장도 | 접안·배 수리·화물 나르기·창고·보급·경비, 배후 거주·어로 | 기지 기능과 소규모 섬 생활을 분리한다. 반경 큰 내륙 마을만 생성하는 규칙으로 포구를 채우지 않는다(`settlement-regions.js:5,20-30`). 기지 철폐가 섬 자체의 삭제를 뜻하지 않는다. |

생활 모델은 같은 집·옷을 일부 공유할 수 있다. 핵심은 온돌 하나·기와 색 하나로 민족을 구별하는 것이 아니라 기후·재료·용도·계층·교환 관계가 조합에 반영되는가이다. 인물의 수를 늘리는 것보다 도구·짐·목적지와 연결된 행동이 먼저다.

## 6. 현실적인 수정 순서와 직접 보아야 할 장면

1. **사건과 생활 공간의 경쟁부터 제거한다.** 경주 643·645·646 동일 카메라에서 주택·전각·인물 척도와 주변 생활권을 유지한다. 기존 중첩 처리 전체를 무조건 삭제하지 말고, 사건이 쓰는 시설·작업 구역을 정해 적용한다. 역사상 실제 파괴·이전은 별도 상태로 남긴다.
2. **시설과 사건·인물의 기간을 분리한다.** 황룡사 645→646→800, 청해진 828→830→851 이후를 먼저 본다. 시설이 남는 것뿐 아니라 공사가 일상 운영으로 바뀌고 현장 인물이 근거 없이 남지 않는지 확인한다.
3. **상경·국내성·가야권·섬 생활을 세계 공간에 연결한다.** 북방 생활 지형과 작고 좁은 해안 취락을 처리하고, 모든 지역을 새 수도 템플릿 하나로 채우지 않는다. 800/920 상경, 400 국내성, 600 김해, 830 완도에서 넓은 지역과 생활 근경을 왕복해야 한다. 가야 정치체가 활동한 400/500년 김해·함안·고령의 추가 공개 근경은 NOT_RUN이다.
4. **이미 확보한 대상의 의미를 모델과 행위에 반영한다.** 황룡사 9층 목탑·사찰과 주조·사리 봉안·석비를 분리한다. 추가로 512년 우산국, 802년 해인사, 851년 청해진을 직접 열어 새 분기와 실제 해안·경사에서의 결과를 검사한다. 이 세 장면의 공개 수용 검사는 아직 NOT_RUN이다.
5. **서로 다른 해·지역의 차이를 별도로 확인한다.** 600년 사비↔경주↔낙동강권, 800년 경주↔상경·지방, 917→918→920년 경주·상경을 비교한다. 다른 모습의 개수는 세지 않고 지위·시설·생활 변화가 출처와 추정 범위에 맞게 설명되는지 본다. 925/926/928 상경과 934/935/936 경주 경계 검사는 후속으로 이어야 한다.
6. **실제 거리 전환에서 기능을 보존한다.** 160/60이라는 파일명만 고집하지 않고 각 도시의 LOD 경계를 측정해 경계 안팎을 오간다. 성벽이 주택 지붕으로 바뀌거나 항구의 접안 관계가 끊어지는지 본다. 같은 기기에서 이동·연도 왕복 뒤 상세 셀과 GPU 자원 증가가 수습되는지 확인하되, 내용 부족을 높은 FPS로 합격시키지 않는다.

총평: 짝의 핵심 미충족 판정은 유지한다. 수정의 핵심은 모델 개수나 국가별 외형 할당이 아니라 **시설·사건·생활·인물의 서로 다른 시간과 공간을 연결하는 것**이다. 12개 제공 이미지 직접 열람, 지정 코드와 장면 데이터 확인, 제한된 기관 자료 대조, 추가 3개 모델 선택 실행까지 확인했다. 이번 검토는 공개 앱을 직접 조작한 검증·새 대규모 사료 조사·실측 복원·장시간 성능 검증이 아니다.
