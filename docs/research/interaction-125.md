# 연도 드래그의 멈춤 — #125

이전 정지·이동 평균 FPS는 연도 막대를 연속 조작할 때의 긴 정지를 설명하지 못했다.
실제 기록으로 1580~1600년 입력21개를16ms 간격으로 전달하고, 마지막 change와600ms 대기를 포함해 측정했다.
1920×1080·RTX3060·medium·같은 로컬 프런트엔드 경로에서 수정 전과 후를 비교했다.
데이터는 실제 c2 API다. 입력 한 번의 동기 처리와 나중에 확정하는 장면 처리 시간을 구분했다.

| 항목 | 수정 전 | 수정 후 |
|---|---:|---:|
| 전체 조작 검사 시간 | 7972.7ms | 1104.5ms |
| input 핸들러 최대 시간 | 552.1ms | 0.2ms |
| 숲 갱신 호출 | 25회 | 2회 |
| 숲 갱신 누적 시간 | 4871.4ms | 33.9ms |

`e91e460f`: 연도 막대를 움직이는 동안 입력값·연표는 즉시 따라가고,120ms 동안 새 입력이 없거나
손을 놓으면 마지막 연도의 역사 장면을 확정한다. 빈 중간 입력마다 지형을 다시 만들지 않는다.
점유 영역·장면 크기·길 상태가 같으면 숲을 재사용한다. 나무 주변 검색은 작은 공간 단위로 제한하고
같은 나무의 크기를 점유 영역마다 반복 계산하지 않는다. 지형·나무 수·그림자·선택 사료 규칙은 유지했다.
확정 단계의 모든 장면 처리가0.2ms라는 뜻은 아니다. [전](interaction-before-125.json)·[후](interaction-after-125.json)의 work와 frames에 확정 비용도 남겼다.

[지형·숲·길 재검사9개](landscape-regression-125.json)와 기존 연대·에셋 JS 검사 통과.
`67f1d79f` 공개판의 [3840×2160 실제 연속 이동 검사](interaction-public-4k-125.json)는 이동133.7fps,
전체 보기164.2fps였다. 렌더 버퍼3500×1822, DPR1, 실제 프레임 간격 기준이며 CPU/GPU·창 크기를 함께 기록했다.
새 연표·가까운 사건 장면 복구도 포함한 측정이다. 저사양 실제 기기는 NOT_RUN, GitHub CI는 workflow0개로 NOT_RUN이다.
