# 초기 파일 요청의 연결 끊김 (#138)

임시 공개판을 새로 열 때 `/app/people.js` 요청이 cloudflared origin 연결 실패로 끝나 화면 초기화가 진행되지 않은 사례가 있었다.
기본 `ThreadingHTTPServer`의 연결 대기 수는 5였다. 실제로 준비가 끝난 뷰어에 정적 파일 요청 64개를 동시에 보내 연결 끊김 13건을 재현했다.
`ViewerServer`의 대기 수를 128로 늘린 뒤 같은 실제 HTTP 검사에서는 64개가 모두 성공했다. [전후 실행 JSON](http-burst-138.json).

변경 전 성공 51/64·최대3,391ms, 변경 후64/64·최대1,875ms다. 작은 로컬 검사이므로 대규모 사용자 수용량이나 인터넷 지연 전체의 개선을 뜻하지 않는다.
서버 재기동 직후 색인이 준비되기 전 실행한 검사는 비교에서 제외했다. 양쪽 본 검사는 정적 파일 응답을 확인한 뒤 수행했다.
[실제 공개판 첫 로딩과 전승 기능 검사](startup-public-138.json)도 15개 통과했다.

임시 뷰어만 33280에서 31088로 재기동했고 Fuseki32068·터널3484는 유지했다. 창을 띄우지 않았다.
c2의 SSH/HTTP 무응답은 별도 #137이며 이번 Windows 연결 대기 수 문제를 c2 장애의 확정 원인으로 쓰지 않는다.
