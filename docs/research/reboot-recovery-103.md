# 2026-09-08 재부팅 후 조사 재개

기존 조사 8개의 CLI 대화 저장본은 재부팅 뒤 찾을 수 없었다. 실제 `--resume` 호출은 모두 `No conversation found with session ID`로 끝났다. 재부팅 전에 남은 이벤트 기록은 보존했고, NUL 바이트로 손상된 입력과 작업 메타데이터를 분리했다. 입력은 저장소와 손상되지 않은 원본에서 복구했다.

복구한 조사 기록과 원래 할 일을 새 **Claude Opus 5 / Max** 세션 8개에 넘겼다. 지역 좌표 조사 1개를 추가해 총 9개를 창 없이 실행했다. 요청 모델뿐 아니라 각 세션의 실제 응답 모델이 `claude-opus-5`인 것도 확인했다. 개발과 자료 통합은 Codex가 맡는다.

작업 폴더는 `%TEMP%/sigong-completion-103/<조사명>`이다. `events.jsonl.before-reboot`, `recovery.json`, `recovered-activity.json`은 복구 근거이고, `*.resume-failed`는 실패한 재개 시도의 실제 출력이다. 현재 `run.json`과 `events.jsonl`은 새 실행 기록이다. 새 실행기는 주요 기록을 flush/fsync 후 교체한다. 원문 파일 저장이 실제 시작됐지만, 이 기록 자체가 조사 완료나 제품 반영을 뜻하지 않는다.

## 장면 통합 코드

`build_history_scenes.py`는 `--collection`, 반복 가능한 `--job`, `--merge`, `--out`을 지원한다. 완료한 시대별 조사만 합치고, 같은 장면 ID의 수정본만 교체한다. 원문 해시와 실제 모델 실행을 확인하는 기존 검사, 시점·장소·참여 근거 연결을 유지한다. 엔터티 ID 연결표는 조사 가져오기 코드와 함께 쓴다.

기존 실제 조사로 재생성한 뒤 병합해 **13개 장면의 좌표·역할·효과·출처가 같고 장면이 중복되지 않음**을 확인했다. 새 조사 결과는 아직 이 검사에 포함되지 않는다. #103과 전체 역사 장면 확장은 계속 진행 중이다. GitHub Actions 워크플로가 없어 CI는 NOT_RUN이다.
