# 검색 중 사료 카드·연도 기록의 파일 읽기 (#74)

운영 `0d158b6`의 전체 원문 2,567,757개에서 뷰어 12개 검사 중 사료 카드와 연도 기록이
두 번 실패했다. 삼국사기 카드 응답은 12.057초, 918년 원문 57개 응답은 11.260초였다.
검색이 없을 때는 각각 0.399초·0.113초였다.
[최초 화면 검사](viewer-before-file-read-fix-74.json), [실제 요청 시간](search-file-reads-74-before.json)

#71은 색인의 파일 변경 확인 중에만 전체 검색이 잠깐 실행 시간을 양보했다.
그 확인이 끝난 뒤 카드 Markdown과 원문 JSONL을 읽는 단계는 검색에 밀렸다.
파일 변경 확인·카드·원문 읽기를 같은 재진입 잠금으로 묶고, 검색은 256행마다
진행 중인 파일 읽기가 끝날 때까지 기다린다. 파일 읽기가 없으면 바로 검색한다.
카드는 파일 읽기 안에서 색인을 확인하므로 재진입을 허용한다.

검색 일치 규칙·사료 선택·전체 수·반환 상한·파일 변경 확인 조건과 뷰어 검사 시간은 그대로다.
사료 카드를 연 뒤 파일과 원문을 바꾸면 바로 새 본문과 chunkCount를 읽는 HTTP 검사를 추가했다.
Python 94개 검사 통과. JavaScript와 RDF 생성 코드는 이 수정에서 바뀌지 않았다.

실험은 실제 삼국사기 행을 반복한 자료와 운영 918년 원문 57개로 구성한 2,566,187행,
실제 데이터 파일 4,946개를 사용했다. 원문 검색 두 건과 카드·연도 읽기를 겹쳤다.
이는 반복 자료 실험이며 운영 전체 원문 검사를 대신하지 않는다.

| 요청 | 이전 | 수정 후 |
|---|---:|---:|
| 사료 카드 | 3.572초 | 0.247초 |
| 918년 원문 | 2.598초 | 0.703초 |
| 평양 원문 검색 | 20.488초 | 18.863초 |
| 광개토왕 원문 검색 | 19.360초 | 17.587초 |

두 검색의 전체 수 33,321개·0개, 반환 120개·0개와 카드·연도 원문 전체 응답의 SHA256이
수정 전후 일치했다. 단순한 주기적 대기로 지연을 충분히 줄이지 못했던 두 시도도
[실험 기록](search-file-reads-74-benchmark.json)에 함께 보존했다.

`2fee775` 운영 반영 뒤 기존 뷰어 **12/12**와 후속 운영 스크립트 7개가 통과했다.
전체 c2 원문에서 두 검색과 카드·연도 조회를 다시 겹친 관측값은 카드 **0.285초**,
연도 원문 **0.974초**다. 검색 전체 시간은 15.954초·14.144초였고 검색 결과는 각각
7,298개·8개, 반환 120개·8개였다. 이는 한 번의 실제 관측값이며 보장 속도는 아니다.
