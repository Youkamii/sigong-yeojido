# #200 개체 이름 원본 정리 결과

기준: `docs/research/copy-style-v2.md` §1 '개체 이름' 행 (사용자 결정 Q7=b). 화면에서만 다듬던 규칙(#197 `displayLabel`)을
원본 데이터 `data/entities/**/*.md` 의 머리말 `label` 에도 적용했다. 브랜치 `feat/entity-labels-200`, 기준 커밋 `abd4e120`.

## 무엇을 했나

이름에서 뗀 정보는 버리지 않고 옮겼다.

| 자리 | 무엇 | 예 |
|---|---|---|
| `label` | 짧게 다듬은 이름 | `일본군` |
| `labelNote` | 이름에서 뗀 설명 (새 머리말 키) | `임진왜란 침입군, 사료 표기 일본군·왜군·적군` |
| `kind: "group"` | '집단 행위자' 꼬리 대신 (새 머리말 키) | 화면에서 '나라'가 아니라 '집단'으로 보인다 |
| `aliases` | 정리 전 원래 이름 (새 머리말 키) | `일본군 (임진왜란 침입군, …) · 집단 행위자` — 찾기가 계속 잡는다 |

규칙은 `services/entity_labels.py` 한 곳에 있고, `scripts/clean_entity_labels.py` 가 그 규칙으로 파일을 고친다.
같은 규칙을 화면(`services/host/app/chronicle.js`)과 대조했다 — 개체 13,323개 전부에 두 구현을 돌려
`displayLabel` 과 같은 이름이 나오는지 확인했고, 뒤에 적은 2건 말고는 전부 같았다.

## 충돌 — 정리하면 이름이 겹치는 것

규칙: 정리 뒤 **같은 유형에서 같은 이름**이 서로 다른 개체에 생기면, `sameEntityAs` 로 이미 한 개체로 묶인 경우가
아닌 한 그 개체들은 **정리하지 않고 원본을 그대로 뒀다**. 새 이름을 지어내지 않았다. 정리 전부터 이름이 똑같던
개체(예: `무오사화 (1498)` 둘)는 이번 정리가 만든 충돌이 아니므로 그대로 정리했다.

- 충돌 묶음 714개, 손대지 않은 개체 1,472개.
- 묶음의 유형: 장소 659, 사건 49, 인물 3, 나라 3.
- 원인별: **HGIS 번호로만 구분되던 행정구역 593묶음**(예: `경상남도/함안군/칠서면 (HGIS 144749)` 와 `… (HGIS 144750)` —
  괄호를 떼면 구분이 사라진다), **같은 사건·인물의 중복 기록 121묶음**(예: `갑오개혁 (1894~1896)` 와 `갑오개혁`).

사건·인물·나라 충돌은 대부분 **교과서 계열 항목과 민족문화대백과 계열 항목이 같은 사건을 따로 적어 둔 것**이다.
이번 작업의 범위 밖이라 병합하지 않고 목록만 남긴다. 대표 예:

| 유형 | 겹치는 이름 | 개체 |
|---|---|---|
| Event | 아관파천 | `event-agwan-pacheon-1896` = 아관파천 (1896년 2월 11일) / `event-mt3-agwan` = 아관파천 |
| Event | 임진왜란 | `event-encykorea-imjinwaeran` / `event-hs-imjin-war` / `event-hs-jl1-imjin-war` = 임진왜란(1592~1598) |
| Event | 신라 경도 지진 | `event-ced-d100` (100) / `event-ced-d304` (304) / `event-ced-d779` (779) — 연도가 유일한 구분 |
| Person | 김무력 | `person-gim-muryeok` = 김무력(金武力) / `person-kim-mulyeok` = 김무력(武力) |
| Person | 조영규 | `person-je-jo-yeonggyu` = …(趙英珪) · 이방원의 문객 / `person-syj103-jo-yeonggyu` = …(趙英圭) · 1592년 양산군수 |
| Polity | 당 | `polity-tang` / `polity-hs4-tang` = 당(唐) / `polity-hs-nbg-tang` / `polity-hs-sg5-tang` |

전체 목록은 `python scripts/clean_entity_labels.py --report <경로>` 로 언제든 다시 뽑을 수 있다(파일을 고치지 않는다).

## 검색·동일성에 준 영향

- **동일성(sameEntityAs) 정본 선택은 이름을 쓰지 않는다.** `services/chronicle_query.py` 의 `priority()` 와
  `services/host/app/chronicle-load.js` 의 `priority()` 는 모두 개체 id 모양과 주장 수로만 정본을 고른다.
  병합 여부도 유형이 같은지만 본다. 그래서 이름을 정리해도 정본 선택은 달라지지 않는다.
- **찾기는 `label` · `labelHanja` · `aliases` 를 함께 본다**(`atlas-data.js` 의 `searchable`). 정리 전 이름을
  `aliases` 에 넣었으므로 옛 이름으로 찾아도 잡힌다. 이 값이 화면까지 가도록 서버가 `/api/chronicle` 응답의 개체에
  껍데기의 `aliases` · `labelNote` · `kind` 를 붙인다(`chronicle_query.apply_shell_names`). Fuseki 에 질의를 더 보내지
  않고, 서버가 이미 읽어 둔 껍데기 목록을 쓴다.
- 지식 그래프에도 남긴다: `services/build_ttl.py` 가 껍데기에 `syj:alias` 3,320개, `syj:labelNote` 3,092개,
  `syj:kind` 83개를 함께 내보낸다.

### 검색 회귀 결과

정리 전/후 개체 목록으로 `atlas-data.js` 의 `search` 를 node 에서 직접 돌렸다(개체 13,323개 전부, 사료 필터·동일성
병합 없이 — 가장 불리한 조건).

- **대표 20개 이름**(세종 · 이순신 · 한산도 대첩 · 일본군 · 안동부 · 아관파천 · 갑오개혁 · 광개토왕 · 을미사변 ·

  **16개는 1순위가 그대로**, 1개(삼일 운동)는 정리 전에도 후에도 결과가 없다(색인에 그 표기가 없다),
  3개는 1순위가 **같은 대상의 다른 기록으로** 바뀌었다.
  - 광개토왕: `person-gwanggaeto` → `person-encykorea-gwanggaeto` (둘 다 광개토왕)
  - 장보고: `event-hs-nbg3-jangbogo`(장보고의 활동) → `person-encykorea-jangbogo`(장보고) — 이름이 정확히 맞는 인물이 올라왔다
  - 동학농민운동: `event-hs-donghak`(동학 농민 운동) → `event-encykorea-donghak-nongmin-1894`(동학농민운동)
  세 경우 모두 정리로 이름이 정확히 일치하게 되면서 동점이 생겼고, 동점에서 다른 중복 기록이 앞선 것이다.
- **정리한 이름 전수**: 정리한 인물·사건 개체의 **옛 이름 733개로 찾아 730개가 자기 자신을 1순위로** 돌려준다(99.6%).
  빗나간 3개(`무오사화 (1498)`, `노량해전 (1598)`, `실성(實聖)`)도 모두 **같은 대상의 중복 기록**이 1순위였다.
- 회귀 테스트는 `tests/entity-label-search.test.mjs` 에 표본으로 남겼다.

## history-scenes.json 전수 대조

`services/host/app/history-scenes.json` 에는 **개체 이름을 베껴 둔 자리가 없다.** 전수로 확인했다.

- `scenes[].participants[]` 는 `entityId` 와 `role` 만 갖는다 — 이름 필드가 없다.
- `scenes[].participantGroups[].label` 276개는 장면별 설명이다. `entityId` 로 개체를 찾을 수 있는 19개를 대조했더니
  **19개 모두 개체 이름과 다른 문장**이었다(예: 개체 `고구려` ↔ 그룹 `백제에서 온 이주민`). 베낀 값이 아니다.
- `scenes[].place.label` 26개와 `scenes[].title` 5개가 이번에 바뀐 옛 이름과 글자가 같지만, 이는 장면의 장소·제목
  표시값이지 개체 이름의 복사본이 아니다(개체와 이어 주는 id 가 없다). 게다가 이 파일은
  `scripts/build_history_scenes.py` 가 `data/research/**` 에서 만들어 내는 파생물이라 직접 고치면 다음 빌드에 지워진다.
  장면 제목·장소 표기는 copy-style-v2 §1 의 '제목' 행이 맡는 별개 항목이다.

`data/entities` 는 digest 대상이 아니다(`services/validate.py` 의 digest 는 `data/claims/<src>/.digests.json` 에만 적용).
그래서 `--write-digests` 는 필요 없다.

## 남은 결함

1. **괄호 안에 `' · '` 가 든 이름 2개는 손대지 않았다.** `부산대학교 박물관 (발굴 조사 기관 · 집단 행위자)`,
   `국립중앙박물관 (발굴 조사 기관 · 집단 행위자)`. 화면 규칙 `displayLabel` 은 `' · '` 를 괄호 안팎 가리지 않고 잘라서
   `부산대학교 박물관 (발굴 조사 기관` 처럼 괄호가 깨진 이름을 보여준다(#197 때부터 있던 표시 버그). 원본 데이터까지
   깨뜨리지 않으려고, 정리 결과의 괄호 짝이 맞지 않으면 원본을 그대로 두게 했다. 화면 쪽 `displayLabel` 을
   괄호 밖의 `' · '` 만 자르도록 고치는 일은 이 작업 범위 밖이라 남긴다.
2. **다시 임포트하면 옛 이름이 되살아난다.** 개체 이름의 출처인 `data/research/**/result.json` 은 이번에 고치지 않았다.
   `scripts/import_*.py` 를 다시 돌리면 정리 전 이름이 되돌아온다. 임포트 뒤에
   `python scripts/clean_entity_labels.py --apply` 를 한 번 더 돌리면 된다(멱등이고, 충돌 판정도 그때 다시 한다).
3. **중복 기록 121묶음은 그대로 남았다.** 같은 사건·인물을 교과서 계열과 민족문화대백과 계열이 따로 적어 둔 것이라
   이름을 정리하면 겹친다. `sameEntityAs` 로 묶는 것이 옳은 처리이고, 이번 작업에서는 이름을 건드리지 않고 목록만 남겼다.
4. **`/api/chronicle` 의 이름 보강은 실제 서버로 확인하지 못했다.** 서버 기동 금지라 Fuseki 를 거친 왕복은 돌려보지
   못했고, `chronicle_query.apply_shell_names` 와 `server.entity_shells` 는 단위 검사로만 확인했다.
5. **인물·장소 카드의 '다른 이름' 줄에 정리 전 이름이 뜬다.** `atlas-story.js` 는 `aliases` 를 '다른 이름: …' 으로
   보여준다. 이제 `광개토왕` 카드에 `다른 이름: 광개토왕 (민족문화대백과)` 가 붙는다. 사실이긴 하나 사람이 부르던
   다른 이름은 아니다. 표시 쪽에서 '정리 전 표기'를 거를지는 다음 화면 작업에서 정할 일이다.
6. **`labelNote` 에 개발 용어가 남는다.** `HGIS 144106` 같은 값이 2,000건 넘게 `labelNote` 로 들어갔다. 이름에서는
   빠졌지만 카드의 이름 옆 설명으로는 보인다. copy-style-v2 §1 의 개발 용어 규칙은 `coordinateNote` 만 다루므로
   이번엔 그대로 뒀다 — 보일 자리가 아니라면 표시 쪽에서 거르는 편이 낫다.
