# 연도 기록의 응답 완료를 기다리는 뷰어 검사 (#89)

기존 검사는 연도 기록 버튼을 누른 뒤 1.5초만 기다리고 본문 카드 수를 확인했다.
[병렬 실행](preserved-route-viewer-initial-88.json)과 [단독 재실행](year-records-viewer-initial-89.json) 모두
918년 패널이 ‘찾는 중…’인 상태에서 카드 0개로 실패했다. 화면과 코드에서 비동기 응답이 끝나기 전임을 확인했다.

실제 `/api/year`를 같은 전체 사료·918년·limit 150으로 호출하니 92개 모두 본문이 있었다.
응답은 137,549바이트였고 외부 주소 1.111초·c2 내부 0.215초였다. 해당 호출의 관측값이며 응답 시간 보장이 아니다.

검사는 기존 사료 카드 검사와 같은 10초 상한에서 ‘찾는 중…’이 사라지기를 기다린다.
918년 제목·실제 본문 카드가 있어야 통과하는 조건을 유지했고 제품 코드·API·제품의 대기 시간은 바꾸지 않았다.
시간 초과·빈 응답·다른 연도·본문 없는 결과는 계속 실패한다.

[수정된 검사로 실제 외부 주소의 12항목이 통과](year-records-viewer-89.json)했다.
이 실행의 연도 기록 대기는 1,320ms, 실제 본문 카드 92개, 브라우저 오류 0개였다.
앞선 두 실패를 삭제하거나 당시 검사도 통과한 것으로 바꾸지 않았다.
