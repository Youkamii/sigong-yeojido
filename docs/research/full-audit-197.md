원인은 문구 수정이 아니라 **재빌드 순서**다. 같은 출처 id 가 여러 묶음 `result.json` 에 서로 다른 제목으로 들어 있고(`src-hs-en-kaesong` 은 `goryeo-early-2` 에 '영문 위키백과', `goryeo-early-3` 에 'Wikipedia'), `scripts/build_history_scenes.py` 의 `sources[sid]=…` 가 나중에 처리한 묶음으로 조용히 덮어썼다. 이 보고서 §"실행 자료"가 적은 "남은 32묶음은 같은 컬렉션끼리 처리" 라는 순서 변경만으로 값이 뒤집힌 것이다. 이 출처들을 `place.coordinateSourceIds` 로 쓰는 장면 26개에서 화면에 "위치 자료 · Kaesong — Wikipedia" 가 그대로 나갔다.

## 실행 자료

`scratchpad-195/`의 기존 `extract.candidates`, `verify.QUOTES`, `apply_claims_direct.value_spans`, `apply_scenes_direct.py`, `check_fix2.py`, `check_fix3.py`를 재사용했다. 이번 작업의 정보 이동·역할 축약 검증은 `audit197_verify.py`에 두었다. 기존 검증기의 “요약 변경 금지”·역할 숫자 자체 보존 조건을 그대로 쓰면 이번 지시와 충돌하므로, 요약·제목·역할·연도 필드를 합쳐 수치와 인용 보존을 확인한다. 이전 실행 자료는 덮어쓰지 않고 `audit197-*`로 저장했으며 누적 `rewrites.jsonl`은 새 수정안과 맞췄다.

claims md 의 `object.value` 를 고치면 같은 작업에서 `python services/validate.py --write-digests` 로 `.digests.json` 을 반드시 다시 기록한다. `audit197_claim_bytes.py` 처럼 바이트를 직접 고치는 경로에도 이 단계를 넣는다. (#197 은 md 11개만 고치고 digest 를 갱신하지 않아 `validate.py` 가 `FAIL [digest-mismatch]` 11건으로 멈췄고 TTL 재생성이 막혔다.)
