# 대용량 사료의 인용 원문 (#68)

전체 원문이 c2에만 있는 실록에도 새 클론에서 검증할 수 있는 주장을 추가하기 위해,
실제 인용한 chunk의 JSON 객체를 원값 그대로 `data/sources/<source>/citation-chunks.jsonl`에 둔다.
본문·기관 날짜·주석·표점·출처 필드를 바꾸지 않는다. 전체 `chunks.jsonl`을 이 작은 파일로 대체하지 않는다.

검증기·TTL 빌더·뷰어는 전체 파일을 먼저 읽는다. 동일 ID가 있으면 JSON 객체 전체가 같은지
대조하고 한 번만 집계한다. 본문뿐 아니라 날짜·주석 등이 달라도 실패한다.
전체에 없는 ID만 인용 원문에서 보충한다. 다른 사료 ID를 같은 폴더에 놓는 것도 오류다.

검사: `python -m unittest discover -s tests -p test_chunk_index.py`.
인용 원문만 있는 상태, 전체와 일치하는 상태, 날짜 메타데이터가 바뀐 상태를 각각 실행한다.
조선실록의 실제 인용 파일과 운영 전체 대조는 #51 반영 기록에 이어 적는다.

`b5b46b8`을 `git archive`로 비어 있는 디렉터리에 풀고, 그 안의 검증기와 추적 파일만으로
실제 검증을 실행했다. Source 996개·chunk 49,003개·Claim 260개, 실패·경고 모두 0이었다.
전체 실록 JSONL은 0개이고, 4개 사료의 인용 원문 11개만 포함된 상태다.
[실행 결과](citation-clean-clone-68.json). c2 전체 원문과 11개 JSON 객체의 일치는
[운영 원문 대조](joseon-citation-corpus-51.json)에서 별도로 확인했다.
