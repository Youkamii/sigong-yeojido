# 신라 이름 주장 3개의 근거 범위 수정 (#85)

원문에 인용 문자열이 있다는 검사만으로는 그 문자열이 주장의 내용을 뒷받침하는지 보장하지 못한다.
기존 세 Claim은 목적어의 뒷부분을 받치는 문장까지 인용하지 않았다. 이미 저장한 JSONL의
원문을 읽어 다음과 같이 수정했다. 새 웹 수집이나 원문 교정은 하지 않았다.

| Claim | 빠졌던 근거와 수정 |
|---|---|
| `claim-silla-name-fixed-jijeung` | 지증 4년 겨울 10월과 `謹上號新羅國王.” 王從之.`까지 같은 기사의 인용에 포함 |
| `claim-silla-name-samgukyusa` | 雞林의 두 유래와 `後世遂定新羅之號.`를 포함. 서로 다른 전승을 하나의 개명 시점으로 요약하던 목적어는 이름 목록으로 고침 |
| `claim-silla-renamed-gyeongju` | `攺新羅爲慶州, 以爲公之食邑.`을 포함. 국호 별칭인 `hasName` 대신 해당 기사 서술인 `describedAs`로 고침 |

세 chunk의 원문·원 철자·날짜 값은 그대로다. 신라와 현재 경주시를 같은 엔티티로 합치지 않는다.
正承公을 받은 사람의 연결이나 관직·봉작 구분을 이 기사에서 새로 추출하지 않았다.

전체 인용·참조 검증은 9,416 Claim, 실패 0·경고 0이다. 목적어/술어가 바뀐 digest 2개를
명시적으로 갱신했다. 나머지 9,414개는 같고 인용만 넓힌 첫 Claim의 digest는 기존 규격상 같다.
Python 110개를 통과했다. 두 번의 전체 빌드가 바이트까지 같고 rdflib 재파싱은
244,941트리플·검사 실패 0이다. #84의 이름 규칙에 따라 충돌 집계는 8개에서 6개가 됐다.

실제 전체 검사를 다시 실행해 통과했다. [이전 산출물 불일치](name-quotes-build-stale-84-85.json)와
