# 원문 검색 중 짧은 주장 조회 지연 (#71)

Source 996개·원문 2,567,024개가 적재된 운영 `b8561ee`에서 평양 다음 광개토왕을 선택하면
주장 13개 응답이 5.015초 걸렸다. 기존 뷰어 검사는 5초 뒤 아직 로딩 중인 화면을 읽어 1건 실패했다.
별도 진단에서 실제 응답 완료와 주장 13개 표시를 확인했다.
[최초 실패](viewer-before-search-fix-71.json), [실제 요청 시간](search-contention-71-before.json)

원문 검색 두 건과 API의 파일 변경 확인이 겹칠 때 Python 스레드 사이에서 CPU를 기다렸다.
파일 변경 확인은 한 번에 하나씩 실행하고, 전체 원문 검색은 그 확인이 진행 중일 때만
256행마다 1ms 양보한다. 검색 이름·사료 필터·전체 수·반환 상한·캐시 갱신 조건은 유지한다.
파일 변경 확인이 없으면 이 대기는 실행하지 않는다. 검사 제한 시간도 그대로다.

원인 확인 실험은 실제 삼국사기 행을 반복한 2,566,130행과 운영 파일 3,341개의 변경 확인을 사용했다.
변경 확인 시간은 18.055초에서 1.697초, 두 검색의 전체 시간은 16.868/18.083초에서
12.361/13.776초였다. 검색 결과는 두 경우 모두 0건·33,320건, 반환 0개·120개로 같았다.
이는 반복 자료 실험이며 운영 전체 원문 수용 검사와 구별한다. [수정 후 실험](search-contention-71-benchmark.json)

서버 단위 검사 16개 통과. 실제 운영 수용 결과는 배포 후 전체 작업표의 운영 검사에 기록한다.
