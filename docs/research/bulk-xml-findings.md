# 국편 벌크 XML 실측 — 우리가 만들려던 게 이미 들어 있다

> 2026-09-05 실측. 대상: 공공데이터포털 `15053635` 삼국사기 원문.
> 재현: `python3 scripts/fetch_datago_bulk.py --dataset 15053635` → `scripts/analyze_bulk_xml.py --dataset 15053635`

2차 조사 비평이 **blocking**으로 남긴 질문이 둘 있었다.

1. 벌크 XML 안에 웹 `levelId`가 보존되는가 — 없으면 근거 추적이 불가능해 프로젝트 전제가 깨진다
2. 유일한 합법적 대량 수집 경로가 실제로 열리는가 — 아무도 파일을 열어보지 않았다

**둘 다 확인했다. 그리고 예상보다 훨씬 많은 것이 들어 있었다.**

---

## 1. 접근 경로 — 열린다

`db.history.go.kr`의 `robots.txt`는 검색봇 4종 외 전면 `Disallow`다. 사이트를 긁는 것은 규약 위반이다.
그런데 국편이 같은 자료를 공공데이터포털에 벌크로 개방해 뒀다. **사이트를 긁을 필요가 없다.**

삼국사기 원문(`15053635`) 상세 페이지에서 직접 확인한 이용허락범위: **"이용허락범위 제한 없음"**

다운로드는 2단계다. 사이트 JS(`/js/biz/datset/script_fileDetail.js`)에서 역추적했다.

```
1. GET  /data/{dataset}/fileData.do
        → fn_fileDataDown('15053635', 'uddi:bc9c…', '', '1', '2') 파싱
2. POST /tcs/dss/selectFileDataDownload.do   (publicDataTyCode=PR0051)
        → JSON: {"status": true, "atchFileId": "FILE_000000002636444", "fileDetailSn": "1"}
3. GET  /cmm/cmm/fileDownload.do?atchFileId=…&fileDetailSn=…
        → sg.zip (882,685 bytes)
```

인증·로그인 불필요. 다만 사이트 JS에 캡차 우회 경로(`check-reset.json`)가 있는 것으로 보아
**과다 요청에는 제한이 붙는다.** 필요한 것만 받는다.

> **주의**: 이용허락범위는 데이터셋마다 다르다. 2차 조사 실측으로 실록·고려사·비변사등록·
> 승정원일기는 "제한 없음"이지만, **각사등록 원문(15053638)과 한국사료총서(15053632)는
> 공공누리 제4유형(출처표시 + 상업적이용금지 + 변경금지)**이다. 변경금지가 붙은 자료를
> chunk로 쪼개는 것이 허용되는지는 미확정이다. 데이터셋마다 개별 확인이 필요하다.

## 2. levelId 보존 — 확인됨

XML의 계층 `id`가 웹 퍼머링크와 **같다.**

```xml
<item id="sg" name="三國史記" org="국사편찬위원회">
  <level1 id="sg_001">
    <level2 id="sg_001_0020">
      <level3 id="sg_001_0020_0010">      ← 기사 단위
```

대조 검증 (2026-09-05):

| | 내용 |
|---|---|
| 벌크 XML `sg_001_0020_0010` | 제목 "시조 혁거세가 즉위하다" / 원문 `始祖姓朴氏, 諱赫居世. 前漢 孝宣帝五鳳元年甲子…` |
| 웹 `db.history.go.kr/id/sg_001_0020_0010` | 제목·원문 **동일** |

즉 **벌크에서 만든 chunk마다 공개 퍼머링크를 붙일 수 있다.** 근거 추적이 성립한다.
국편이 도움말에서 권장하는 인용 형식(`/id/{기사ID}` + 접근일)과도 일치한다.

**주의 — 무효 id는 404가 아니다.** 없는 id를 요청하면 200을 주면서 조용히 상위 페이지로
폴백한다(2차 조사 발견). 응답 크기·본문으로만 구별된다. 검증기에 반드시 폴백 탐지를 넣는다.

이 발견은 1차 조사가 "삼국사기 기사 단위 ID 규칙 미해결"로 남긴 항목도 해소한다 —
5,170개 기사 ID가 벌크 안에 전부 있다.

## 3. 안에 들어 있는 것 — 삼국사기 하나 기준

| 항목 | 건수 | 우리 스키마의 어느 층 |
|---|---:|---|
| 기사 (`level3`) | 5,170 | Chunk |
| **교감주 (판본 이문)** | **2,741** | **Claim** |
| 원주 | 598 | Claim |
| 색인어 (`index`) | 14,653 | Entity |
| 구조화 날짜 (`dateOccured`) | 3,948 | TimeSpan |
| 주제분류 (`subjectClass`) | 8,704 | Event 유형 |

색인어 내역: 이름 7,551 · 지명 4,613 · 국명 1,780 · 관서 469 · 서명 240

### 3-1. 교감주 = 판본 충돌이 이미 구조화돼 있다

이게 가장 큰 발견이다. 우리가 "여러 판본이 서로 다르게 말하는 것을 담겠다"고 설계한 층이,
국편 데이터에 **이미 태그로 들어 있다.**

```xml
<annotation id="sg_001_0010_r003" type="교감주">
  <noteContent>정덕본에는 祇로 되어 있고, 을해목활자본에는 祗로 표기되어 있다.
               한국정신문화연구원본에서는 祇를 따랐다.</noteContent>
</annotation>
```

이 한 조각이 그대로 Claim 세 개다 — 정덕본의 주장, 을해목활자본의 주장, 정문연본의 채택.
그리고 각각이 어느 기사(`sg_001_0010`)의 어느 자리인지도 id로 박혀 있다.

**삼국사기 하나에서만 2,741건이다.** 판본 충돌 시연에 억지 사례를 만들 필요가 없다.

### 3-2. 날짜 — 원표기를 보존하며 접미사의 뜻은 미확인

```
-0057-04-15L0   → 기원전 57년 4월 15일    (음수 = 기원전)
-0053-01-99L0   → 기원전 53년 1월, 일 미상  (99 = 미상)
-0050-99-99L0   → 기원전 50년, 월·일 미상
```

`L`의 공식 뜻은 아직 **미확인**이다. 2026-09-06 고순종실록 ZIP 전수 집계에서 1896년 이후에도
`L0` 18,891건이 나왔으므로, `L`만 보고 음력이라고 단정하지 않는다. 끝자리 `1`과 윤달 표기의 관계는
고려사 652건에서 일치했지만 공식 규격은 찾지 못했다. `99`는 표본 라벨에서 월·일이 없는 경우와
대응한다. 이 관찰을 전체 날짜 규격의 확인으로 넓히지 않는다.

DTD 확인, 전수 수치, `LO` 예외 1건과 글자 차이 조사는 [날짜·글자 조사](date-and-character-format.md)를 따른다.

우리 스키마 §8의 `precision` 필드가 이 인코딩과 거의 그대로 대응한다.
다만 이건 **국편이 한 변환이지 원문 자체가 아니다.** 원문은 간지·연호로 적혀 있고,
서기 환산은 국편의 판단이 개입한 결과다. 따라서 `dateOccured`도 **국편 판본의 Claim으로**
취급해야지 사실로 박으면 안 된다.

### 3-3. 색인어 — 개체가 태깅돼 있다

```xml
<index type="이름">赫居世</index>
<index type="지명">閼川</index>
<index type="국명">前漢</index>
```

인명 7,551 · 지명 4,613건이 본문 안에 인라인으로 붙어 있다.
LLM으로 개체를 처음부터 뽑을 필요가 없다 — **이걸 씨앗으로 삼고, 태깅 안 된 것만 보강**하면 된다.

다만 색인어는 **표기 단위이지 개체 단위가 아니다.** `南堂`이 5번 나오면 5건으로 세어진다.
동일 개체 판정은 여전히 우리 몫이고, 스키마 §10대로 그 판정도 Claim이다.

## 4. 프로젝트에 미치는 영향

**비용이 크게 준다.** chunk·개체·날짜·주제 분류를 처음부터 만들 필요가 없다.
LLM의 역할이 "사료를 읽고 구조를 만든다"에서 "이미 있는 구조를 검증하고 빈 곳을 채운다"로 바뀐다.

**그렇다고 검증이 면제되지는 않는다.** 국편 데이터도 한 기관의 편찬 결과물이다.
교감주는 국편이 고른 판본들의 대조이고, `dateOccured`는 국편의 환산이며,
색인어는 국편의 개체 판정이다. 전부 `src-nikh` 판본의 Claim으로 들어가야지
"사실"로 들어가면 안 된다 — 그렇게 하면 우리가 판정하지 않겠다고 한 선언이 무너진다.

**다음에 할 것**

- 다른 데이터셋에도 같은 구조가 있는지 확인 (고려사·실록·삼국유사)
- `history.dtd` 전문을 읽어 태그 사양을 확정 — 특히 `dateOccured`의 `L`과 끝자리 숫자
- 국편 XML → 우리 스키마 변환기 설계. 교감주 → Claim 매핑이 핵심
- 각사등록·한국사료총서의 공공누리 4유형 "변경금지"가 chunk 분해에 걸리는지 확정
