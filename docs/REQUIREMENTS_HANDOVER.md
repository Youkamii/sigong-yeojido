# 시공여지도: 사용자 요구사항과 작업 인수인계

작성일: 2026-09-12 · 문서 이슈: [#178](https://github.com/Youkamii/sigong-yeojido/issues/178)

이 문서는 사용자가 대화에서 반복해 밝힌 요구사항과, 문서 작성 시점의 작업 상태를 보존한다. 다음 작업자는 이 문서를 먼저 읽고 [기존 인수인계](HANDOVER.md)의 운영·자료 설명을 이어서 확인한다. 과거 문서의 기능 검사 PASS를 현재 사용자 요구사항의 완료로 해석하지 않는다. 이후 사용자의 새 지시가 우선한다.

## 1. 목표와 우선순위

**시간을 바꾸며 한반도의 역사와 사람들의 삶을 탐험하는, 크고 상세한 3D 세계를 만든다. 시대·지역마다 실제로 어디에 사람들이 모여 살았고 무엇을 했는지가 화면에서 보여야 한다.**

우선순위는 사용자가 탐험할 수 있는 구체적인 역사·생활 장면, 실제 거주 분포, 시대·지역에 맞는 디테일이다. 지형과 기술 구조는 이를 뒷받침한다. 산을 정교하게 만드는 일이나 에셋 개수를 늘리는 일이 이 목표를 대신하지 않는다.

가장 최근의 핵심 지시:

> “랜덤하게 남기지 말고 도시나 사람들이 많이 사는 위치가 있을거아냐..제발 그런거 신경좀 써”

> “왜 저렇게 하나하나 디테일하게 못해주냐는거야”

사용자는 요구사항을 여러 번 충분히 설명했다. 다시 같은 내용을 질문하게 만들지 말고, 다음 항목을 실제 장면으로 구현한다. 고인돌·밭·호랑이·빌딩 등 사용자가 든 예시는 필요한 요소를 찾아 구성하라는 뜻이며 전체 목록이 아니다.

## 2. 변하면 안 되는 제품 요구사항

### R01. 넓고 탐험 가능한 3D 세계

- 한반도 모양의 넓은 지도에서 자유롭게 이동하고 확대할 수 있어야 한다.
- 한반도의 역사와 사람·사건·정주 공간을 담을 충분한 규모를 확보한다. 작은 기본 디오라마로 압축하거나 모든 에셋을 함께 줄여 문제를 가리지 않는다.
- 제공된 판톨로지 화면과 레퍼런스처럼 건물·거리·사람·생활 장면을 세밀하게 구성한다.
- 판톨로지의 모델링 코드뿐 아니라 에셋 사용법, 크기 관계, 배치와 장면 구성까지 참고한다.
- 지형·건물·인물의 크기와 밀도가 서로 어울려야 한다. 빛기둥이나 나라 하나만 보이는 화면으로 대신하지 않는다.
- 핵심 탐험 경험은 3D 지도다. 별도 그래프나 에셋 목록을 이 경험의 대체물로 만들지 않는다.

### R02. 실제 거주 위치와 밀도

- 시대별 실제 도시·취락·사람이 모여 살던 지역을 먼저 정한다.
- 수도, 지방 중심지, 항구, 상업·공업 지역, 농어촌은 규모·밀도·구성이 달라야 한다.
- 도시의 성장·이동·쇠퇴와 주변 생활권의 변화를 반영한다. 현대 도시의 위치와 범위를 모든 과거 연도에 그대로 적용하지 않는다.
- 전국 격자에서 임의로 마을 위치를 뽑거나, 지형이 평평하다는 이유만으로 집과 밭을 흩뿌리지 않는다.
- 이름 없는 생활 배경은 허용한다. 다만 그 시대·지역의 거주와 생업 맥락에 맞게 배치한다. 임의 배치는 정해진 생활권 안에서 개별 집·소품의 세부 구성을 만드는 데 사용한다.
- 자료가 부족한 곳을 자동 배치로 채운 뒤 역사적 거주 분포를 구현했다고 보고하지 않는다. 필요한 자료를 찾아 실제 배치에 연결한다.

### R03. 시대·지역·용도에 맞는 외형

- 인물의 복식, 주거, 마을, 도시, 생산 시설은 시대와 지역에 따라 달라야 한다.
- 선사 취락, 고대 도성, 고려·조선의 도시와 읍성, 개항기·일제강점기의 변화, 현대 주거·상업·공업 지역을 구분한다.
- 2010년 서울·부산 같은 도시 중심지를 밭과 작은 농촌 집으로 표현하면 실패다.
- 현대 북한 지역도 현대의 도시·생활 모습으로 표현한다. 자료 부족을 이유로 1700년대 건물로 되돌리지 않는다.
- 같은 문화에서 공유하는 부품은 재사용할 수 있지만, 완성된 마을 한 덩어리를 전국에 복사하지 않는다.
- 큰 도시, 지방 도시, 촌락, 항구, 공업 지역 등의 규모와 기능 차이가 읽혀야 한다.

### R04. 하나하나 연결된 생활 장면

- 집, 골목, 장터, 작업장, 창고, 밭, 항구와 사람들의 행동을 연결한다.
- 주거–생업–저장–운송, 생산–작업–완성품–교역처럼 사람들이 그곳에 사는 이유가 드러나야 한다.
- 같은 집·밭을 반복하거나 집 수만 늘리는 방식으로 밀도를 채우지 않는다.
- 가까이 들어갔을 때 그 장소에서 사람들이 무엇을 하며 살아가는지 볼 수 있어야 한다.
- 건물과 길의 겹침, 밭을 가로지르는 길, 물 위 건물, 과도한 크기, 뜬 장면 등을 스스로 찾아 고친다.
- 성·부락·교역·생산·교육·종교·공공 생활 등 지역에 필요한 요소를 스스로 보완한다.

### R05. 인물과 사건을 함께 보여주기

- 그 해에 살아 있는 인물뿐 아니라 실제 사건과 현장을 보여준다.
- 핵심 인물은 눈에 들어와야 하며, 왜 그 위치에 있고 그때 무엇을 했는지 근거가 있어야 한다.
- 생몰 기간만으로 인물을 임의의 지도 위치에 놓지 않는다. 이순신이 한반도 중앙에 놓였던 문제가 대표적인 실패 사례다.
- 전쟁은 관련 위치의 전투·상륙·화재·함선 등으로 성격이 드러나야 한다. 사건 종류에 맞는 참여자와 행동을 구성한다.
- 핵심 인물과 관련 사건을 함께 볼 수 있게 한다.
- **유지할 좋은 경험:** 이순신을 누르면 해당 현장으로 확대되고 그 안의 장면이 보이는 방식. 다른 인물·사건에도 자연스럽게 이어간다.

### R06. 시간에 따른 유지·변경·퇴장

- 요소는 유효한 기간 동안 유지한다. 매년 전체를 새로 만들지 않는다.
- 도시의 존속, 이름 변경, 수도 역할, 시설의 사용 기간, 사건, 인물의 활동 기간을 구분한다.
- 한양이 수도였던 기간에는 수도 역할을 표시한다. 이름이나 행정 지위가 끝났다는 이유만으로 도시의 생활 자체가 사라지면 안 된다.
- 해당 시기에 존재하지 않았던 지명과 행정 명칭을 표시하지 않는다. 1500년에 ‘서울특별시’가 나오는 것은 실패다.
- 사건·활동은 기간이 끝나면 빠지고, 다음 사건·활동이 들어와야 한다. 중요하지 않은 일회성 요소를 오랫동안 남겨두지 않는다.
- 준공 사건이 끝났다고 사용 중인 건물이 사라져서는 안 되고, 건물을 유지하려고 건설 인물과 사건 기간까지 연장해서도 안 된다.
- 연도가 불분명한 설화·구전은 별도로 선택해 볼 수 있게 한다. 모든 연도에 상시 노출하지 않는다.

### R07. 전 시대·전 지역의 내용

- 특정 연도나 유명 사건 몇 개에 치우치지 않는다. 선사부터 현대까지 역사적·문화적 분위기를 담는다.
- 북부·중부·남부·제주 등 지역별 삶과 역사 내용을 충분히 구성한다.
- 사건이 없는 해에도 도시와 생활이 이어져야 한다.
- 제주를 한 시점만 확인하지 말고, 여러 시대에 걸친 모습과 변화를 검토한다.
- 사용자가 빈 연도와 지역을 하나씩 찾아 지적하게 만들지 않는다.
- 모든 자료를 무조건 수집할 필요는 없지만, 화면이 계속 비거나 같은 모습인 상태를 완성으로 보지 않는다.

### R08. 지리·영토·확장

- 한반도 형태와 위도·경도를 일관되게 사용한다. 인물·사건·지역·경계가 같은 좌표 체계를 따라야 한다.
- 강과 주요 산맥, 울릉도·독도를 표현한다.
- 산봉우리를 전부 강조할 필요는 없다. 백두산·한라산·당시 수도 등 중요한 지점을 우선한다.
- 지형은 실제 한반도의 인상을 살리되 역사와 생활 장면보다 우선하는 목적이 아니다. 대동여지도 같은 전체 인상을 고려한다.
- 시대별 국가 영토를 보여주고, 나뉜 영역이 어느 국가인지 알 수 있게 한다. 신라가 어느 시기에 어디까지였는지 탐색할 수 있어야 한다.
- 중국·일본 일부도 보여준다. 장차 지구 규모로 확장할 수 있는 방향을 유지한다.
- UI 변경을 하면서 한반도 형태나 강을 임의로 바꿨던 실수를 반복하지 않는다.

### R09. 시간선과 화면 조작

- 연도 숫자를 직접 입력할 수 있어야 한다.
- 좌우 시간 조작은 처음에 1년씩 움직이고, 계속 조작하면 점점 빨라져야 한다. 놓으면 멈춘다.
- 시간선에 마우스를 올리면 손 모양 커서 등 조작 가능함을 보여준다.
- 하단 핵심 사건들이 선택한 연도에 맞춰 좌우로 따라와야 한다.
- 지역명 등 표시 요소를 선택적으로 켜고 끌 수 있어야 한다.
- 제공된 UI 이미지의 방향을 반영한다. 입장 화면은 너무 어둡지 않아야 한다.
- 사건·인물 선택, 현장 확대, 시간 이동이 하나의 서비스처럼 자연스럽게 이어져야 한다.

### R10. 디테일을 유지하는 최적화

- 이동·확대·연도 변경이 원활해야 한다. 화면이 멈추는 상태는 실패다.
- 같은 표시 기간에는 객체를 재사용하고, 변화가 있을 때 갱신한다.
- 보이지 않는 뒷면 등 불필요한 렌더링을 줄인다. 필요한 지역의 상세 표현에 자원을 쓴다.
- 멀리서 단순하게 그리더라도 건물의 종류·높이·형태·위치는 유지한다. 멀어지면 아파트가 낮은 지붕집으로 바뀌면 안 된다.
- 그림자가 일부에만 이상하게 적용되는 문제를 해결한다.
- 최적화를 이유로 지도 전체를 줄이거나 생활 장면을 비워서 해결하지 않는다. 사용자 기기의 실제 탐험 경험으로 확인한다.

### R11. 자료·근거·온톨로지

- 공신력 있는 사료·기관 약 5종을 중심으로 필요한 내용을 충분히 확보한다. ‘5종’은 역사 사건을 다섯 개만 넣으라는 뜻이 아니다.
- 인물·사건·장소·시기·관계·근거를 연결해 이후 온톨로지로 활용할 수 있게 한다.
- 조사는 문서에만 쌓지 말고 실제 지도·외형·배치·행동으로 연결한다.
- 익명 생활 배경과 특정 역사 인물·사건·유적의 사실 주장을 구분한다.
- 자료 부족이 실제 위치·시기·행동을 틀리게 그리는 이유가 되어서는 안 된다. 보강할 내용을 식별하고 조사한다.

### R12. 작업 방식과 완료 기준

- Codex가 개발 총괄·리딩·통합을 맡는다. 최신 개발용 하위 에이전트 지정은 **GPT-6 Astra low**다.
- 조사·수집은 실제 **Claude Opus 5 / Max effort**를 호출해 맡긴다. 다른 모델로 수행한 일을 Claude 조사라고 보고하지 않는다.
- 사용자는 필요한 병렬 작업을 허용했다. 시대별 평가에는 최소 6개 max → 두 배인 **12개**, 그 절반은 각각 적대적으로 지적하도록 요청했다. 과거 개발 모델 제한보다 이후의 명시 지시를 따른다.
- 불필요한 워크플로를 늘리지 않는다. 기존 코드 방식을 따르고 변경을 작고 읽기 쉽게 유지한다.
- 브랜치·워크트리를 사용한다. 사용자와 Claude의 병렬 작업을 덮어쓰지 않는다.
- 기능별 GitHub 이슈를 먼저 만들고 이슈별 커밋을 남긴다. 푸시·공개 반영 여부를 구분해 보고한다.
- 터미널·브라우저 창이 불필요하게 뜨지 않게 한다. Windows 하위 프로세스는 숨겨 실행한다.
- 외부 고정 주소에서 접속할 수 있어야 하고, 재부팅 때마다 임시 주소를 다시 만들거나 수동으로 살릴 필요가 없어야 한다.
- **매년 제대로 검증한다.** 일부 표본 연도만 보고 전체 연도를 검증했다고 하지 않는다.
- 코드 실행, 화면 렌더링, 실제 역사·문화·시각 적합성을 각각 확인한다. 테스트 PASS·보고서·이슈 생성만으로 완료라고 하지 않는다.
- 사용자 입장에서 부족한 디테일과 이상한 장면을 먼저 찾아 수정한다. 완료 후 실제 접속 링크를 제공한다.

## 5. 다음 작업자가 진행할 일

1. **사용자 레퍼런스와 실제 최신 화면을 직접 본다.** Threads 미디어도 확인한다. 반복된 지적을 작은 외형 수정으로 축소하지 않는다.
2. **시대별 거주 분포를 먼저 보완한다.** 선사·서기 초 공백, 시대별 수도와 지방 중심, 북부·남부·제주, 도시의 성장·이동·쇠퇴를 점검한다. 필요한 조사는 실제 Claude Opus 5 / Max에 병렬로 맡기고 원문·좌표·연대를 산출물로 받는다.
3. **배치와 장면 구성을 함께 고친다.** 자료 구역 50개와 현대 프로필 12개만으로 충분한지 판단한다. 도시·농촌·생산·항구의 밀도와 연결, 개별 건물·길·행동의 디테일을 실제 화면에서 확인한다. 평양·서울·제주에 같은 완성된 배치를 복사하지 않는다.
4. **시간·위치·행위의 남은 오류를 해결한다.** 아래 열린 이슈의 세부 범위를 확인하고, 이미 들어간 일부 수정과 미완 범위를 구분한다. 건물 준공과 사용 기간, 발굴 연도와 선사 취락 점유 연도, 후원과 현장 참여를 혼동하지 않는다.
5. **최종 소스와 실제 로드된 자료로 매년 다시 검증한다.** 자료·모델 검사, 실제 렌더링, 지역별 역사·문화·시각 검토를 나눠 기록한다. 한 장의 전체 지도나 콘솔 오류 0개로 모든 지역이 적합하다고 판정하지 않는다.
6. **최종 사용자 경험과 성능을 확인한 뒤 반영한다.** 기능별 이슈·커밋·원격 SHA와 공개 반영을 연결한다. 문서·PR·테스트만 끝내고 사용자에게 수정을 완료했다고 하지 않는다.

브라우저 실행은 창을 표시하지 않는 Python Playwright를 사용한다. 이 PC에서는 Chrome 실행 파일 `C:\Program Files\Google\Chrome\Application\chrome.exe`와 아래 모듈 경로를 사용해 임시 촬영을 실행했다. 재사용 검사기는 아직 실행하지 않았으므로 먼저 작은 범위로 동작을 확인한다.

```powershell
Set-Location C:/Users/gkfkd/Git/sigong-annual-world
$env:PYTHONPATH = Join-Path $env:TEMP 'sigong-pw95'
py -3.12 scripts/verify_every_year_browser.py --repo C:/Users/gkfkd/Git/sigong-annual-world --out <새-결과폴더> --start 2009 --end 2011
# 동작을 확인한 뒤 --start/--end를 생략하면 전체 범위다.
```

Claude 조사 실행 경로는 기존 HANDOVER의 운영 설명을 따른다. 확인한 실행 파일은 `C:\Users\gkfkd\AppData\Roaming\npm\node_modules\@anthropic-ai\claude-code\bin\claude.exe`, 기존 숨김 실행 도우미는 `%TEMP%\sigong-claude-run.py`다. 요청 모델·effort뿐 아니라 실제 응답 모델과 종료 상태를 남긴다. 새 조사는 아직 실행하지 않았다.

서버 상태 확인과 운영은 [배포 문서](deployment.md)를 따른다. 미완 앱 브랜치를 문서 전달과 함께 배포하지 않는다. 기존 사용자 서비스·터널을 불필요하게 다시 만들거나 재시작하지 않는다.

## 7. 완료 판단에서 반복하지 말아야 할 오류

- 사용자가 요구한 상세한 세계를 ‘기존 코드에 붙이기 쉬운 자동 배치’ 수준으로 낮춰 해석했다.
- 집 수·모델 종류·테스트 통과를 장면의 역사적·문화적 완성도로 취급했다.
- 문제를 확인한 보고서와 이슈를 만들고도 실제 수정을 끝내지 않은 채 작업을 마무리했다.
- 이름·역할·사건의 기간을 도시·시설의 존속과 섞었다.
- 한 해나 한 지역만 고치고, 다른 시기·지역과 거리에서 같은 문제가 남는지 확인하지 않았다.
- 가까운 건물만 고쳐놓고 원거리 표현이 다시 낮은 지붕집으로 바뀌는 것을 놓쳤다.
- 출처 있는 생활권을 실제 화면에 연결하지 않은 채 임의 마을과 밭으로 빈 공간을 채웠다.

다음 작업의 완료 기준은 위 요구사항이 실제 탐험 화면에서 충족되는 것이다. 아직 부족하면 부족한 상태와 남은 작업을 정확히 기록하고 계속 구현한다.
